# 설계 과정에서 고민한 내용과 결정

프로젝트에서 검토한 대안과 선택 이유를 정리한다. 선택한 방법이 모든 상황에서 최선이라는 뜻은 아니며, 현재 데이터와 실험 범위에서의 결정이다.

## 1. 학습에 없는 단수명 사례를 어떻게 다룰까?

**고민:** Train에 500 미만 수명이 없으므로 기존 데이터 몇 행을 가공하여 수명 사이클을 낮추면 도움이 될까?

**결정:** 원본 정답은 바꾸지 않고 셀을 복제하지 않는다.

기록을 잘라 짧게 만드는 것과 실제 셀이 일찍 수명을 다한 것은 다르다. 정답을 임의로 줄이면 초기 측정값과 실제 수명 사이의 관계를 훼손한다. 초기 피처를 개선할 수는 있지만 새로운 단수명 실험 사례가 생기는 것은 아니다.

현재는 범위 차이를 EDA와 오류 분석에서 명시하고, 실제 단수명 데이터 확보를 개선 방향으로 남겼다.

## 2. 피처 엔지니어링으로 무엇을 바꿀까?

**고민:** 절대 용량 수준보다 변화 정도가 배치 차이에 덜 민감할까?

**결정:** 평균 Qd 제외, 상대 용량 변화, ΔQ 정규화, 온도·내부저항 변화 후보를 비교한다.

상대 용량 변화는 `(91~100 평균 - 2~11 평균) / 2~11 평균`으로 계산한다. 정규화 ΔQ는 해당 셀의 2~11사이클 평균 Qd로 나눈다. 온도·내부저항 변화는 같은 앞·뒤 구간 평균의 차이다.

계산식의 해석이 가능하고 초기 100사이클 안에서 계산할 수 있는 후보를 사용했다. 새 피처를 무조건 채택하지 않고 CV로 비교했다.

## 3. 새 피처를 안 쓰는 비교 기준은 무엇일까?

**고민:** ‘원본 데이터만 사용’이라는 표현을 원시 배열을 그대로 모델에 넣는 방법으로 볼 것인가?

**결정:** 측정값 정리·분할·결측 대체·표준화는 같게 하고, 이후 모델에 선택되는 피처 구성을 다르게 한다.

기존 피처 모델도 ΔQ와 초기 요약 피처를 사용한다. 새 변화·정규화 피처를 제외한다는 뜻이지 전처리나 기존 피처 계산을 생략한다는 뜻이 아니다.

## 4. 후보를 미리 줄일까, 단계별로 남길까?

**고민:** 비교 범위를 줄이면 계산은 빠르지만 다른 모델에 유리한 피처를 너무 일찍 제외할 수 있다.

**결정:** 초기 후보군은 유지하고, 기본 CV → 분기별 선별 → 확장 피처 → 생존 후보 매개변수 탐색 순서로 진행한다.

모델·정답 변환·피처 그룹별로 후보를 남긴다. `top_k_stage1`, `top_k_stage2`로 탐색량을 조절하고, 생존·탈락 이유를 기록한다. 모든 조합의 최적해를 보장하는 방식은 아니다.

## 5. 0.5% 개선을 채택 기준으로 둘까?

**고민:** 작은 점수 차이를 구분하기 위해 고정 개선 기준이 필요할까?

**결정:** 0.5% 또는 0.5%p를 자동 채택 기준으로 사용하지 않는다.

현재 표본에서 해당 차이가 의미 있다고 판단할 근거가 확정되지 않았다. CV 평균과 변동, 후보 복잡도를 함께 살펴보고 기존 선택 규칙을 적용한다. 단계별 유지 개수는 계산량 설정이며 통계적 유의성 기준이 아니다.

## 6. Batch2에서 가장 좋은 구성을 최종 모델로 고를까?

**고민:** Train CV 순위와 Batch2 성능 순위가 다를 때 어느 결과를 따라야 할까?

**결정:** 모델·피처·매개변수는 Train 내부 CV로 선택한다. Valid와 Batch2 결과는 평가·해석에 사용한다.

Batch2 점수로 다시 선택하면 평가 데이터에 맞춘 선택이 된다. 후보별 Batch2 결과를 제시하더라도 사후 비교로 구분한다. Batch2가 탐색 과정에서 관측됐다는 한계도 유지한다.

## 7. 휴지 조건이나 newstructure를 모델에 넣을까?

**고민:** 같은 C-rate라도 수명이 다르고, 무전류 그룹과 단수명 집단이 연결돼 있다면 이를 피처로 넣어야 할까?

**결정:** 현재는 설명용 그룹과 사후 오류 분석에만 사용한다.

cycle5에서 `|I|<0.01A`인 연속 구간의 최장 시간을 계산하고 2분 초과 여부로 그룹을 나눈다. 이는 실험 패턴의 구분이며 특정 공식 휴지 단계나 고장 원인을 확정하는 기준은 아니다.

평가 배치에서 발견한 집단 특징을 즉시 입력에 추가하지 않았다. 접미사와 무전류 조건도 평가 셀 집단에서 겹쳐 개별 효과를 분리할 수 없다.

## 8. 전체 열화 곡선과 Knee는 어디까지 사용할까?

**고민:** 전체 용량 기록이 열화 설명에 유용하지만 초기 예측 시점에서는 알 수 없는 정보다.

**결정:** 전체 Qd 곡선은 EDA 설명에만 사용한다. 후기 기록·기록 종료·Knee는 모델 입력에서 제외한다.

예측 피처는 최초 100사이클 안에서만 계산한다. 전체 곡선의 정규화는 셀별 초기 기준으로 형태를 비교하기 위한 표시이며, 새로운 모델 입력이 아니다.

## 9. 노트북과 main.py를 어떻게 함께 유지할까?

**고민:** 두 실행 방식에 학습 코드를 각각 작성하면 수정할 때 결과가 달라질 수 있다.

**결정:** `ExperimentRunner`의 공통 코드를 사용한다.

노트북은 단계를 셀별로 실행하고, main.py는 같은 단계를 연속 실행한다. 설정은 config.py에서 관리한다. 두 방식의 분할·CV 결과·최종 구성·셀별 예측·지표 일치를 확인했다.

## 10. 결과와 그래프를 어디에 남길까?

**고민:** 별도 결과 파일을 늘리지 않으면서 분석을 확인하고 저장소에서도 그래프를 보여주고 싶다.

**결정:** 표·예측 결과는 노트북 출력에 남기고, 그래프만 assets/에 PNG로 저장한다.

EDA 11개와 성능 그래프 2개는 고정 파일명을 사용하며 재실행하면 덮어쓴다. 결과 CSV·모델 파일은 생성하지 않는다.

## 11. Batch3와 논문 성능을 어떻게 다룰까?

**결정:** Batch3는 원본 보관만 하고 로딩·EDA·전처리·학습·평가에서 제외한다.

논문의 9.1%는 참고값으로 비교하되, 현재 배치·분할·피처·학습 절차가 동일한 재현 실험이라고 주장하지 않는다. 최종 Batch2 MAPE 40.396%와의 GAP은 약 31.296%p이며, 조건 차이와 현재 단수명 과대 예측의 한계를 함께 해석한다.

## 현재 결론

상대 용량 변화가 포함된 Ridge·로그 정답 구성이 CV에서 선택됐다. 기존 피처 대표보다 Batch2 오차는 낮아졌지만 단수명 과대 예측이 남았다. 피처 엔지니어링만으로 학습 데이터에 없는 수명·실험 조건의 문제를 해결했다고 볼 수 없다.
